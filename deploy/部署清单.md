# Docker 部署清单

一套 `docker compose up -d` 起全套：MySQL + Redis + 后端 + Nginx。
数据库、Redis 只在 compose 内网可达，公网只暴露 80/443。

```
浏览器 ──► Nginx(:80/:443)
            ├── /           → 学生端 dist（静态）
            ├── /admin/     → 管理端 dist（静态）
            └── /api/       → app 容器(:8081, 仅内网)
                                ├── mysql 容器（仅内网，数据落 mysql-data 卷）
                                └── redis 容器（仅内网，缓存 + 登录限流）
```

## 〇、服务器初始化（腾讯云 OpenCloudOS 9）

首次登录服务器后做这几件事，一次配好。

### 1. 装 Docker 与 Compose（系统已预置腾讯 docker-ce 源）

```bash
sudo dnf update -y
sudo dnf install -y docker-ce --nobest docker-compose-plugin
sudo systemctl enable --now docker

docker --version && docker compose version   # 两个都有版本号即成功
```

### 2. 配置镜像加速（不做的话拉不动 Docker Hub）

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net"
  ]
}
EOF
sudo systemctl restart docker
docker pull hello-world    # 能拉下来即加速生效
```

`mirror.ccs.tencentyun.com` 是腾讯云**内网**镜像源，服务器上免流量且快。

### 3. 放行端口（两层都要，漏一层就是"连接超时"）

**腾讯云控制台 → 轻量/CVM 实例 → 防火墙（安全组）**，放行入站：

| 端口 | 用途 |
|---|---|
| 22 | SSH（默认已开） |
| 80 | HTTP |
| 443 | HTTPS（暂时只放行规则，启用 TLS 后即用） |

**系统内 firewalld**：OpenCloudOS 9 最小化镜像**不预装** firewalld（命令不存在就是没装），
无需处理——控制台安全组是实际生效的过滤层，它放行了就够了。
本机没有额外防火墙挡路，直接继续。
（若你的镜像带了 firewalld，执行：`sudo firewall-cmd --permanent --add-service={http,https} && sudo firewall-cmd --reload`。
注意 Docker 发布的端口走自身 iptables 链、不受 firewalld 管控，host 防火墙只是锦上添花。）

### 4. SELinux（OpenCloudOS 9 默认 Enforcing）

SELinux 可能拦截 bind 挂载（nginx 读不到 dist、compose 起不来）。先正常部署，
如果遇到 `Permission denied` 类报错：

```bash
# 临时放行（重启失效），先验证是不是 SELinux 的锅
sudo setenforce 0
```

确认是它之后二选一：测试环境改永久关闭
（`sudo sed -i 's/^SELINUX=enforcing/SELINUX=disabled/' /etc/selinux/config` 后重启）；
讲究一点就给挂载目录打标签
（`sudo chcon -Rt container_file_t /opt/club-system/frontend /opt/club-system/admin`）。

### 5. 建部署目录

```bash
sudo mkdir -p /opt/club-system/target /opt/club-system/frontend /opt/club-system/admin
sudo chown -R $USER /opt/club-system
```

## 一、本地构建（Windows，Git Bash）

```bash
cd demo

# 1) 后端 jar（务必 clean，否则可能混入旧产物）
./mvnw clean package -DskipTests

# 2) 学生端 dist
cd frontend && npm run build && cd ..

# 3) 管理端 dist（admin/.env.production 已配好 /admin/ 子路径，直接构建即可）
cd admin && npm run build && cd ..
```

## 二、上传到服务器

目标目录建议 `/opt/club-system/`。需要上传（结构与本地 demo/ 保持一致，构建上下文才对得上）：

```
/opt/club-system/
├── deploy/                          ← demo/deploy 整个目录
│   ├── docker-compose.yml
│   ├── nginx.conf
│   ├── Dockerfile
│   ├── .env                         ← 从 .env.example 复制后填写
│   └── sql/schema.sql
├── target/demo-0.0.1-SNAPSHOT.jar   ← 后端 jar（对应 Dockerfile 的 COPY 路径）
├── frontend/dist/                   ← 学生端产物
└── admin/dist/                      ← 管理端产物
```

```bash
# 本地打包上传示例
scp -r demo/deploy user@服务器IP:/opt/club-system/
ssh user@服务器IP "mkdir -p /opt/club-system/target /opt/club-system/frontend /opt/club-system/admin"
scp demo/target/demo-0.0.1-SNAPSHOT.jar user@服务器IP:/opt/club-system/target/
scp -r frontend/dist user@服务器IP:/opt/club-system/frontend/
scp -r admin/dist user@服务器IP:/opt/club-system/admin/
```

## 三、填写 .env（服务器上）

```bash
cd /opt/club-system/deploy
cp .env.example .env
chmod 600 .env

# 生成三组强口令与密钥
openssl rand -base64 24   # → MYSQL_ROOT_PASSWORD
openssl rand -base64 24   # → DB_PASSWORD
openssl rand -base64 48   # → JWT_SECRET
openssl rand -base64 24   # → REDIS_PASSWORD
```

- `CORS_ORIGINS` 留空 = 只有同域能调 API（本方案就是同域，留空即可）
- `DEEPSEEK_API_KEY` 不配则 AI 助手不可用，其余功能正常

## 四、启动与验证

```bash
cd /opt/club-system/deploy
docker compose up -d --build

# 看启动状态（mysql 首次初始化约半分钟）
docker compose ps
docker compose logs -f app     # 看到 Started DemoApplication 即成功

# 验证
curl -s http://127.0.0.1/api/club/list                    # → {"code":200,...}
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1/  # → 200（学生端）
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1/admin/  # → 200（管理端）
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1/api/club-member/club/1  # → 401（名单已收口）
```

数据库只在**首次启动且数据卷为空**时执行 `schema.sql`（9 张表 + 5 分类 + 1 个引导管理员）。

## 六、HTTPS（有域名后尽快做）

前提：域名已备案并解析到服务器 IP（腾讯云国内服务器必须备案）。

**方式 A：腾讯云免费证书（推荐，控制台点几下）**

1. 腾讯云控制台 → SSL 证书 → 申请免费证书（DV，每年 50 张）→ 绑定你的域名，验证用 DNS 或文件均可
2. 签发后下载 **Nginx** 格式，得到 `.crt` 和 `.key` 两个文件
3. 上传到服务器并启用：

```bash
mkdir -p /opt/club-system/deploy/certs
scp 域名_bundle.crt 域名.key user@服务器IP:/opt/club-system/deploy/certs/
# 重命名为 fullchain.pem / privkey.pem（nginx.conf 模板用的名字）
cd /opt/club-system/deploy/certs
mv 域名_bundle.crt fullchain.pem && mv 域名.key privkey.pem
```

**方式 B：certbot（Let's Encrypt，自动续期）**

```bash
sudo dnf install -y epel-release
sudo dnf install -y certbot
sudo certbot certonly --webroot -w /opt/club-system/frontend/dist -d 你的域名
sudo cp /etc/letsencrypt/live/你的域名/fullchain.pem /opt/club-system/deploy/certs/
sudo cp /etc/letsencrypt/live/你的域名/privkey.pem  /opt/club-system/deploy/certs/
```

**两种方式共同的最后一步**：按 `nginx.conf` 底部注释模板启用 443 块 + 80 跳转，
放开 `docker-compose.yml` 里 `"443:443"` 与 certs 挂载，然后：

```bash
docker compose up -d nginx
curl -s -o /dev/null -w "%{http_code}\n" https://你的域名/    # → 200
```

## 七、日常运维

```bash
# 更新后端：本地重新 clean package → 上传 jar → 重建 app 容器
docker compose up -d --build app

# 更新前端：重新构建 dist → 上传覆盖 → 无需重启（目录挂载）
# 注意管理端 dist 必须带 /admin/ 基路径构建（.env.production 已配好）

# 看日志
docker compose logs -f app      # 后端
docker compose logs -f nginx    # 访问日志

# 每日备份（crontab -e 加一行，保留 7 天）
0 3 * * * cd /opt/club-system/deploy && docker compose exec -T mysql sh -c \
  'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" club_system' \
  | gzip > /opt/backup/club_$(date +\%F).sql.gz

# 恢复备份
gunzip < club_2026-11-01.sql.gz | docker compose exec -T mysql sh -c \
  'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" club_system'
```

## 八、常见问题

| 现象 | 原因与处理 |
|---|---|
| `docker compose up` 卡在 Pulling，最后超时 | 镜像加速没配或失效——见第〇步第 2 节重配 daemon.json |
| nginx 一直 restarting，日志 Permission denied | OpenCloudOS 的 SELinux 拦了挂载——见第〇步第 4 节 |
| 浏览器访问超时，但服务器上 curl 正常 | 腾讯云控制台安全组没放行 80/443，或 firewalld 没加规则 |
| **更新 dist 后页面没变 / 403，但 `ls` 里文件是对的** | 重传时删了 dist 目录再重建——容器还挂着旧目录的"幽灵挂载"。`docker compose restart nginx` 重新解析挂载即可。**规避**：更新前端用 `scp -r dist/. 目标路径/`（尾部 `/.` 表示覆盖内容、不删目录），就永远不用重启 |
| app 反复重启，日志 `Could not resolve placeholder 'JWT_SECRET'` | .env 没填或没生效，确认 `.env` 与 compose 同目录后 `docker compose up -d` |
| app 起来了但报「生产环境启动失败」 | JWT 仍是 dev 密钥或 DB 口令太弱——StartupSecurityCheck 拦的，换强值 |
| 管理端页面白屏，控制台 404 | admin/dist 不是用 /admin/ 基路径构建的，在 admin 目录重新 `npm run build` |
| AI 助手没有逐字输出 | Nginx 的 `proxy_buffering off` 被改掉了；或 DEEPSEEK_API_KEY 未配 |
| 时间差 8 小时 | app 容器的 `JAVA_TOOL_OPTIONS` 时区参数被移除，恢复它 |
| 想换端口/加域名 | 改 nginx.conf 的 `server_name` 与 compose 的端口映射即可，后端不用动 |
